# VanJee 720-16 live baseline on Jetson AGX Orin

## Environment

- **Date / device:** 2026-11-24; VanJee 720-series stream decoded as
  `vanjee_720_16`; exact product model and firmware not independently confirmed.
- **Hardware:** NVIDIA Jetson AGX Orin Developer Kit, aarch64, 8 CPUs;
  `schedutil`, no CPU affinity.
- **OS:** host Ubuntu 22.04.5 LTS, Linux `5.15.148-tegra`, Jetson Linux
  R36.4.3; container Ubuntu 22.04.4 LTS.
- **Driver:** `hardware.lidar` 0.1.0, hardware repository revision
  `bb3d3e3028b60dac2bb88a2f3a63c52a6c520fcc` (driver sources unchanged);
  declared VanJee SDK 2.2.9; Bazel 8.8.1, `-c opt --config=dev`.
  The dev configuration used local Core/common/messages/transform overrides;
  their exact revisions at measurement time were not recorded.
- **Workload:** live 10 Hz, 20 s warmup, 1,800 s measured, IMU enabled,
  host clock, UDP `192.168.10.6:3333` to `192.168.10.3:3001` on `eth1`.
  Allocation and channel probes were enabled; `perf` was disabled.
- **Host conditions:** shared host, unpinned; load average was approximately
  22 before the run and 36 afterwards. CPU and latency are not isolated.

The [sanitized baseline JSON](vanjee-720-16-orin-2026-11-24.json) retains the
measured data and source fingerprints; machine-specific paths, hostname and
thread IDs are omitted. Environment and driver fields were supplemented from
the measurement host after the run. The benchmark implementation was
uncommitted during measurement, so its fingerprints are recorded in the JSON
rather than presented as a committed version.

## Reproduction and limitations

Use the [VanJee live procedure](../guides/driver-benchmark.md#vanjee-720-16-live-10-hz-baseline)
with the addresses and ports above, 20 s warmup, 30 min duration, `--no-perf`
and an authorized passive observer to reproduce the packet metrics. Use a fresh
output directory. Match driver and dependency revisions where available and
record the actual revisions and firmware for each new run.

The SDK sent its normal read-only calibration queries. Startup reported missing
calibration file paths; angle and IMU parameters were loaded into memory, not
persisted. IMU output was not measured. The header-to-callback metric is not
hardware-to-driver latency; device clocks were not synchronized. Packet gaps
observed on a separate socket do not establish driver socket delivery, and the
copy counter cannot prove end-to-end zero-copy. Rerun on an idle host before
attributing the observed high tail latency to the driver.
